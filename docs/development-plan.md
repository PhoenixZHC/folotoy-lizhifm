# 荔枝 FM 设备直连开发方案

> 2026-11-12 / Ubuntu 开发电脑：本文为项目启动时的原始开发方案，接口阻塞、资源估计和未实施说明均属于历史阶段；正式1.0状态以CONTEXT.md、user-guide.md及delivery-validation.md为准。

日期：2026-11-10（Asia/Shanghai）。目标设备：FoloToy AI Passport，ESP32-C3，8 MiB Flash，无 PSRAM。阶段：开发准备，接口与实机验证未完成。

## 1. 目标与完成标准

设备通过 Wi-Fi 直接访问荔枝服务和音频 CDN，收听用户在荔枝 FM 已关注博主的节目。日常使用不依赖中转服务、RSSHub、NAS、常驻电脑或手机音频转发。手机可承担必要的账号授权或初始输入，但不是运行期音频源。

完整首版应具备：

1. 恢复有效会话并同步账号关注列表；失效时明确提示重新授权。
2. 浏览博主、分页获取节目、显示标题/时长/发布时间，播放可访问的公开节目。
3. 播放、暂停、音量、上一集/下一集、显式快进/快退菜单。
4. 保存最近收听记录，重新启动后恢复节目和已播放位置。
5. 网络异常、接口限制、节目不可播、格式不支持均有明确反馈，不伪装成空列表或成功。
6. 完成真实关注列表对照、分页、长节目、弱网恢复、内存及重启恢复验收。

手动添加博主仅是验证阶段的能力。如果最终无法可靠获取账号关注列表，应明确判定“完整目标受阻”，重新与用户确定范围，不能静默以本地订阅替代。

本次任务只完成文档、来源可追溯的代码复制和准备验证，不直接实现上述功能。

## 3. 路线比较与选择

| 路线 | 优点 | 代价 | 本项目决策 |
| --- | --- | --- | --- |
| 设备请求荔枝 JSON 接口及 CDN | 不需要服务器，分页小数据适合嵌入式 | 非官方接口、认证与 TLS 内存需要验证 | 采用，先做证据验证 |
| 设备抓网页解析音频 | 可用于了解公开节目来源 | 网页体积、页面结构、防护和解析成本不稳定 | 只作研究，不作为默认实现 |
| 服务端解析/RSSHub/音频代理 | 集中修复方便、可转换格式 | 需要运维并违反本次纯设备直连方向 | 不纳入默认架构或静默回退 |

若直连接口被证实不适用于目标设备/账号，记录原因并暂停依赖该接口的功能；保留可复用固件，不自动切换路线。

## 4. 运行架构

```text
三键 + LVGL 界面（只派发命令，不阻塞）
        │
        ▼
lizhi_app / lizhi_app_logic（浏览状态与播放状态分离）
        │
        ├─ 单 API worker → lizhi_direct_client → 荔枝 HTTPS
        │                    ├─ session / follows（验证后实现）
        │                    └─ programs / resolve（验证后实现）
        │
        ├─ podcast_store → 独立 NVS：账号、本地博主、最近进度
        │
        └─ 播放 worker → audio_stream → 音频 CDN → MP3 → BSP I2S
                                ├─ 下载任务 + 有上限流队列
                                └─ 解码任务 + 已播放采样计时
```

只允许一个 API worker 拥有会话和 API TLS，避免并发使用句柄。播放前释放闲置 API 连接；播放中主动浏览结束后及时释放。封面最低优先，失败不影响声音。不得因封面失败跳过音频错误检查。

每个异步结果带请求序号、账号代次和页面代次。用户切换博主、退出页面或退出账号后，丢弃旧结果，避免把过期列表绘制到新页面。停止播放先取消并等待下载任务，再销毁队列和解码资源。

## 5. 直连接口验证与账号方案

### 5.1 先恢复真实可访问性

先用 2～3 个实际关注博主的分享链接做验证；当前未提供这些链接，不能用虚构账号和节目代替。

记录以下最小证据，原始数据仅放忽略目录 `.local-backup/`：

- 分享链接最终跳转、博主 ID 与电台号的关系。不同页面的 `band`、用户 ID 不得混用。
- 原始 HTTPS 主机名、路径、方法、状态码和必要请求头；保留证书校验。
- HTTP 403 的响应类型、是否为 HTML 拦截页，以及 Ubuntu、手机网络与设备网络的差异。
- 返回体大小、JSON 层次、空列表行为、分页末尾、重复项、删除节目和字段缺失。
- 音频地址的主机、跳转、时效、请求头、真实格式、Content-Length 和 Range 行为。

403 不做无限重试，不猜测有权限的接口，不将任何临时 IP 固定进固件。只有真实证据证明需要时，才设置对应的 User-Agent/Referer/会话条件；不随意添加一组浏览器头声称解决。

电脑请求通过后必须复测 ESP32 的 DNS、SNTP、TLS、重定向与正文读取；电脑成功不等于设备成功。

### 5.2 账号与关注同步是独立关口

用用户自己的有效会话，通过合法可观察的客户端行为确认：登录/授权方式、关注分页、稳定用户 ID、会话有效期、刷新和退出语义。尚未验证的方法不写成已实现接口。

优先采用可验证的授权方式：若存在可用扫码/设备授权则采用；如果只能手动导入会话，需要单独确定是否接受这个产品体验，再实现短时本地配置入口。不得要求用户在聊天中发送 Cookie、密码或令牌，不直接搬运网易云二维码流程。

关注列表应支持分页和去重，使用稳定博主 ID，不以昵称作为主键。刷新先形成有效结果，成功后再替换旧数据。网络失败保留旧列表并标注过期，不能清空成“未关注任何人”。账号退出/切换应隔离会话与关注缓存，处理未完成请求，防止混入前一账号数据。

手机参与授权不改变“设备直连”定义；常驻手机请求代理或音频转发不属于此方案。

## 6. 数据模型与边界

以下是待实现的设备内部模型，不是荔枝 API 的既定协议：

| 模型 | 内容 | 限制 |
| --- | --- | --- |
| Author | `author_id`、昵称、封面 URL | 所有外部 ID 用十进制字符串，避免浮点 JSON 导致大整数丢精度 |
| Episode | `episode_id`、`author_id`、标题、发布时间、时长、可播放状态 | 保留“未知时长”；缺失与 0 区分，不用标题去重 |
| Page | 条目、下一页依据、是否存在下一页、获取时间 | 翻页方式经真实响应确认；仅当响应有效才推进游标 |
| Media | 当前音频 URL、格式、验证器、长度、可用时效 | URL 不是永久标识；播放/恢复前可重新解析，不持久保存临时签名 URL |
| Progress | 账号本地标识、节目/博主 ID、播放毫秒、已播字节/帧锚点、资源验证器、更新时间 | 下载到队列的字节数不等于用户已经听到的位置 |

建议初始资源上限（设计起点，非实测容量）：每页 8 集、最多 3 页紧凑元数据、当前节目列表之外不展开完整历史；标题最多 192 个 UTF-8 字节，ID 最多 32 字节，URL 最多 2048 字节。超长标题按 UTF-8 边界截断并提示，超长 URL/ID 明确拒绝，不能截断后请求。

API 正文初始上限建议 16 KiB；真实 8 条响应超限时，先缩小 `pageSize` 或实现有上限的逐条解析，不无限扩容。`Content-Length` 缺失、分块传输、gzip 和非 JSON 返回都要有明确处理；不在正文未完整读取时解析成成功。上限与最终字段长度在接口验证后校准。

统一结果至少区分：成功、需授权、授权过期、禁止访问、频率限制、网络失败、响应格式变化、内容不可播、格式不支持、内存不足。HTTP 错误码与可脱敏的服务端错误原因保留，不输出完整鉴权头或带签名 URL。

## 7. 音频、快进和断点恢复

### 7.1 先限定 MP3

沿用 Helix MP3 和现有下载/解码任务。不能只凭 `.mp3` 后缀或 `Content-Type` 判断兼容性，还要验证实际数据和帧头。若目标节目为 AAC、M4A、HLS 等，首阶段明确标为不支持并统计真实占比；不默认加入全部解码器，不引入代理转码改变直连方向。

设备只缓冲少量音频，不下载整集到 RAM/Flash。8 MiB Flash 包含固件和 NVS，不作为长播客离线仓库。延续 16 KiB 下载队列及 8 KiB 预缓冲策略作为起点，实测后调整。

### 7.2 区分三种恢复

1. **同次播放掉线续传**：当前下载器保留解码状态，按已入队字节请求 Range。只能在字节、总长度与验证器一致时拼接，不能把它当成重启续听。
2. **重启后续听**：按节目 ID 重新解析 URL，验证资源，恢复到已听位置附近。不能使用“下载偏移”充当播放偏移。
3. **用户快进/快退**：需要时间到帧/字节的映射和解码器重新预热。先验证 CDN 对相应音频的 Range 支持，再增加音频接口。

CBR 可用帧/码率估算，但应排除 ID3 等非音频区域。VBR 优先使用有效 Xing/VBRI 索引；缺失索引时不能按文件长度等比跳转并承诺准确。MP3 bit reservoir 需要前置帧预热，具体回退范围经真实文件验证；避免从任意字节直接发声。

资源验证器变化时，不把旧偏移直接套到新音频。服务器忽略 Range 返回 200 时，明确报告当前不能准确恢复，允许用户主动选择从头播放；不静默重播并显示原进度。接近末尾应确认正常结束再标记已听完，不因网络读断就自动下一集。

### 7.3 持久化

使用独立 `lizhi_*` NVS 命名空间，不能沿用 `netease_session`。版本化存储并验证长度、类型和版本；写入失败不显示“已保存”。最近记录初始最多 20 集，避免保存无限历史。

进度定时保存建议 60 秒一次；暂停、主动切集和退出时按需要刷新，合并重复写入，不能每秒写 Flash。断电最多损失一个保存周期附近的进度，验收时测量。退出账号、删除本地记录及凭证生命周期应区分，不能顺手清除 Wi-Fi 或其他应用 NVS。

## 8. 三键交互

沿用原项目的列表、状态栏、主题和首键只唤醒规则：

- 首页：账号状态、关注博主、最近收听、设置。验证阶段另标“本地添加博主”，避免冒充账号关注。
- 博主页：节目按发布时间展示，↑↓选择，OK 打开/播放，翻页有明确加载状态。
- 播放页：OK 暂停/继续；↑↓上一集/下一集，切换前保存进度。
- 长按 OK：导航菜单，含返回、音量、快退 15 秒、快进 30 秒、从头播放、刷新和设置。
- 封面可延后加载；不实现同步歌词、转写、大段节目全文和复杂动画。

快进/快退在能力未通过验证时禁用并说明原因；界面与后端能力一致。长按和短按不能重复触发，加载完成不抢回用户已离开的页面。

## 9. 内存与并发约束

- Flash 余量不是 RAM 余量。API TLS、CDN TLS、JPEG、音频队列和 I2S DMA 的峰值需要分别测量。
- 沿用直连 TLS 证书校验及动态缓冲策略，不关闭校验证书来省内存。
- API worker 串行取列表，播放前销毁闲置 API TLS；不沿用播放中后台推测性预取。
- 活跃播放时封面失败可延期，核心音频/列表请求失败必须可见。先保证声音再增加封面并发。
- 记录最小空闲堆、最大连续空闲块、任务栈余量与连续切页后的回收情况。没有实测前不宣称某固定 RAM 余量足够。
- 队列满、分配失败、请求取消均有路径；不给请求无限排队。释放页面必须使过期 worker 失去 UI 引用。

## 10. 代码迁移顺序与模块接口

实际已复制路径见 [代码复用](code-reuse.md)。下面的新文件均为计划，不是当前已存在功能：

1. `firmware/components/lizhi_direct_client/`：新增 HTTP、JSON 解析、列表、媒体解析、会话生命周期；公共 API 的结果采用上一节的分类。先实现无网络依赖的响应解析测试，再接真实 HTTP。
2. `firmware/ai-passport/main/lizhi_app_logic.[ch]`：新增关注/博主/节目分页、请求代次、播放选择、错误状态与三键导航的纯逻辑。
3. `main/lizhi_app.[ch]`、`main/lizhi_direct_adapter.[ch]`：worker、显示和协议之间的适配。只将必要字段传给 UI，不传完整原始 JSON。
4. `main/podcast_store.[ch]`：NVS 版本与错误处理、账号隔离和进度。先约定存储格式，再实现写入。
5. `audio_stream`：新增独立的带起点启动/定位能力，保留旧 `audio_stream_start(url)` 语义。seek API 只有在时间映射和 HTTP 行为确定后才定签名，不能先写一个忽略参数的实现。
6. `main/main.c`、`main/CMakeLists.txt`、`Kconfig.projbuild`：只有荔枝最小流程可运行时才切换默认入口与链接依赖。新增 `sdkconfig.lizhi.defaults`，保留必要 TLS/Wi-Fi 预算，去除网易云特有配置。
7. 最后调整 CMake 项目名、版本号、UI 文案、NVS 命名空间和打包器产品名；源码删除另行取得授权，不在准备阶段批量清理。

不要全局把 `netease` 替换成 `lizhi`：二维码授权、加密协议、数据模型和缓存语义不通用。`direct_stream.c` 的有上限解析思路可参考，不能假设适用于未经验证的荔枝返回。

### 批次 C：公开节目最小播放器

- [ ] 有上限的响应解析；覆盖缺失字段、HTML 错误页、超大正文、重复 ID、空页、非法 URL。
- [ ] 本地博主 → 节目分页 → 播放 → 暂停/音量/切集；明确显示验证阶段。
- [ ] 使用真实 MP3，播放至少 60 分钟；验证正常结束、用户取消和读断区别。
- [ ] 主动浏览与播放交错、反复切页、内存不足和 Wi-Fi 恢复均不崩溃。

退出条件：设备直连公开节目播放成立，不代表账号关注目标已完成。

### 批次 D：账号关注与持久续听

- [ ] 关注缓存、账号切换隔离、失效重授权；所有页对照去重，不沿用旧 20 歌单/512 歌曲限制。
- [ ] 按已播放位置保存，重启重新解析节目，资源变更拒绝拼接。
- [ ] 覆盖 CBR/VBR、文件头、Range 200/206/416、URL 过期、末尾恢复与 seek 预热。
- [ ] 快进/快退误差验收目标：有可靠索引的受支持 MP3 不超过 5 秒；没有可靠定位条件时明确不支持，不标为通过。

退出条件：重启续听、账号关注、异常处理和三键完整流程均在设备验证。

### 批次 E：交付验收

- [ ] 主机回归与独立荔枝固件构建通过，清晰区分两类结果。
- [ ] 至少一集 60 分钟以上连续播放，一集自然结束并正确切下一集。
- [ ] 分别测试人工断网重连、播放中浏览、重启续听、会话过期、节目删除/不可播和长列表。
- [ ] 内存与栈余量记录没有持续泄漏；跟踪功耗和热点弱网听感，不复用旧网易云结果。
- [ ] 干净 NVS/PHY、严格 8 MiB 打包、SHA-256、许可证及可复现构建说明齐全。
- [ ] 烧录、发布和破坏性存储验证按授权执行；不把准备阶段产物当正式版本。

## 12. 当前缺口

需要后续提供真实博主链接与账号授权验证条件，才能推进业务协议实测。荔枝登录、关注列表、URL 时效、音频格式分布、设备网络兼容和长时表现均未验证。

本项目选择设备直连，并不意味着已经证明直连可行；开发顺序必须先消除数据接入风险，再扩大界面和播放能力。
