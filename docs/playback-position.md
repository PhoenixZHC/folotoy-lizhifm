# 播放定位与最近续听

更新时间：2026-11-12（Asia/Shanghai）；来源设备：Ubuntu 开发电脑。当前正式版1.0，最新验证见[交付记录](delivery-validation.md)。

本模块提供帧锚点定位和设备本地续听，已接入真实账号作用域和最近四集。早期探测与样本证据在下文按原阶段保留，不代表当前账号功能受阻。

## 实现

- `audio_position`：纯帧头解析、带余数采样时钟、64个约1秒间隔帧锚点、资源身份与恢复边界检查。Layer III支持MPEG1/2/2.5的已知码率帧；free-format等不支持情形明确失败。
- `audio_stream`：增加 `audio_stream_start_at` 和已输出进度的checkpoint；保留旧 `audio_stream_start` 从头语义。目标前约1秒预热bit reservoir和解码状态，丢弃目标前PCM，再开始输出。整帧输入后才调用Helix，避免输入不足时消费帧头破坏锚点。
- `audio_download`：增加从已验证字节起点启动；保留有上限流队列、取消和等待退出。206、范围、总长度和ETag/Last-Modified严格一致才允许续传；缺失验证器也拒绝。
- `lizhi_progress`：独立NVS、账号或local作用域、版本/长度/数字ID/CRC检查。最近四集按ID去重移首，第五集淘汰；兼容旧单条记录，保存时升级。每60秒及暂停/停止合并保存，错误保持可见；不保存音频URL或账号凭据，不修改原网易云NVS。
- `lizhi_app`：播放菜单快退15秒、快进30秒；首页“最近播放”显示四条名称与进度，主动选择续播；列表切回未听完节目同样读取历史。按节目ID重新解析媒体并验证资源，锚点过远或无可靠身份时拒绝跳转，不按文件长度猜测时间。

复用单API worker及音频停止/等待退出顺序；历史列表只在页面临时分配，保存复用应用栈。账号范围与未绑定本地历史分开，不能把local记录当作账号云端历史；内存预算及实测见交付记录。

## 早期实机验收步骤（历史）

1. 保持热点，进入博主列表播放一集至少20秒，长按确定进入菜单。
2. 测试快进30秒、快退15秒：观察时间、听音，确认没有错误、爆音或静默从头重播。若服务拒绝Range，应显示失败，不能记作通过。
3. 暂停并停止返回，长按回首页，确认出现第二条“继续”入口。
4. 重启设备，联网后从该入口恢复：确认节目及位置正确、实际有声音；不得只凭进度数字验收。
5. 60分钟、弱网、VBR更多样本、资源变化/Range异常和存储故障的实机验收仍需后续完成。

本批固件写入及启动证据在实施记录；交互、新增NVS写入/读取和重启恢复尚待用户实际操作确认，不能称完整播放器交付。
